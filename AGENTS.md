# AGENTS.md — Polyglot Market (megarepo витрина)

> **Суть:** точка входа для ИИ-агентов. L0-файл: читать целиком перед любой работой.
> **Связанное:** [docs/README.md](./docs/README.md) — карта и панель «Сейчас»

Монорепа-витрина «1 API — 2 бекенда (Laravel, NestJS) — 7 фронтов (quasar, vue2, angular, react, nuxt, next, sveltekit)»: маркетплейс с общим OpenAPI-контрактом, общей PostgreSQL и MinIO, панелью управления процессами и фабрикой автономных экстракт-репо. Тир dev-standard: T2. Ключевые принципы: контракт — источник правды; активен один бекенд; явные `pnpm doctor/setup/start` без postinstall-магии; целевая платформа WSL2/Linux/macOS (Windows — только через WSL2); везде TypeScript на Node-стороне. Состояние: фазы 1–4 готовы (полный E2E-матрица 2×7 зелёная), фаза 5 «фабрика и витрина» — в работе (осталось видео и публикация — автор).

## Окружение (проверка перед работой)

| Что | Команда |
|---|---|
| Проверка окружения | `pnpm doctor` |
| Установка/настройка | `pnpm setup` (install + .env + infra + migrate + seed) |

| Миграции / сиды | `pnpm db:migrate` / `pnpm db:seed [--force]` / `pnpm db:reset` |

| Laravel-бекенд (:8010 локально) | `cd backend/laravel && php artisan serve --port=8010` |
| NestJS-бекенд (:3000) | `cd backend/nestjs && pnpm build && node dist/main.js` |
| Линт / типы (корень) | `pnpm lint` / `pnpm typecheck` |
| Панель управления (:5555) | `pnpm start` (tsx scripts/panel/manager.ts; проверено, сессия 02) |
| E2E Playwright | `pnpm --dir packages/e2e test` (channel:chrome; E2E_FRONT_URL; через pw-run.mjs — кэш в репу, не в temp) |
| E2E матрица 2×7 | `pnpm e2e:matrix` (поднимает бекенды по очереди + фронты, db:reset на пару; `--back=`/`--pairs=`) — 14/14 + сквозной кейс |
| Полный локальный прогон | `pnpm check:all` (spectral + юниты + conformance + E2E живой пары) |
| Мусор тестов в temp ОС | `node scripts/check-temp.mjs` (`--clean` — удалить найденное; следы проекта в %TEMP% = красный) |
| Матричный тест фабрики | `node scripts/test-extracts.mjs` (14 экстрактов в .cache/extract-matrix, состав+git+lockfile) — 14/14 |
| Смоук docker-образов фронтов | `node scripts/test-docker-fronts.mjs` (`--front=<имя>`; нужна живая infra:up) — 7/7 |
| k8s-стенд (kind в WSL2, фича 18) | `pnpm k8s:up` / `pnpm k8s:down` / `pnpm k8s:status` — витрина http://localhost:8080 (SPA + /api → NestJS), postgres :55432, S3 :59002 |
| Юниты Laravel | `cd backend/laravel && vendor/bin/phpunit tests/Unit` — 7/7 |
| Юниты NestJS | `pnpm --dir backend/nestjs test` (vitest) — 7/7 |
| Фабрика экстрактов | `pnpm extract --front=<имя> --back=<имя> [--ci] [--dry-run]` |

Особенности: **порты этой машины** — laravel на 8010 (8000 занят соседним docker-проектом `engineering-family`, см. ADR-009), nestjs 3000, панель 5555 (план), postgres 5432, s3 9002 (console 9003); k8s-стенд — витрина 8080, postgres 55432, S3 59002 (фича 18, ADR-012). Инфра живёт в WSL-docker (дистрибутив Ubuntu-24.04); при недоступности образа MinIO — s3rver-fallback на :9002 (ADR-008), в k8s-стенде S3 — s3rver-образ pm-s3rver. Реестры машины: docker.io и GitHub доступны, ghcr.io заблокирован (поэтому kind, а не k3d). Демо-аккаунты всех ролей `*@demo.dev` / пароль `password` (сидами). Схема БД меняется ТОЛЬКО общими SQL-миграциями `shared/db/migrations` (ADR-002); artisan-миграции и TypeORM synchronize запрещены. Сгенерированный SDK `packages/api-client` коммитится; перегенерация требует Java (ADR-004). Секреты — только локальные `.env`; JWT_SECRET общий у обоих бекендов (токены взаимозаменяемы, проверено). Windows-native не поддерживается — WSL2 (ADR-009).

## Правила

- Язык: идентификаторы — английский; комментарии и доки — русский.
- **Подробные логи — обязательны (требование автора, 2026-10-19):**
  1. Лог сессии в `docs/log/` фиксирует хронологию работы: какие команды гонялись, какие
     ошибки упали (с дословными сообщениями/кодами), как чинились, какие прогоны и с какими
     числами зелёные. Не «настроил инфраструктуру», а «infra:up упал: pull access denied для
     minio/minio → s3rver-fallback на :9002, креды minioadmin через реестр аккаунтов».
  2. Факты о тестах и проверках — в activity-журнал: `devst log add tests.green "..." --ref путь`.
     Агент пишет факты (зелёный/красный), вердикты человека не сочиняет.
  3. Грабли окружения, которые переживут сессию, — в ADR «Последствия/Дополнения» и в лог.
- Стиль кода: `docs/architecture/NN-code-style.md` **[обязательно для агентов]** (появится в фазе 1).
- Архитектуру менять только с ADR — в момент решения.
- Требования автора фиксируются дословно, протоколом решений в фича-доке (источник — опрос из 40 вопросов, 2026-10-19).
- Каждый новый эндпоинт контракта = conformance-кейсы в том же PR (ADR-005).
- Если есть docs/ui-freeze.md — его статусы абсолютны: 🔒🔒 не редактировать вообще
  (спроси автора), 🔒 — только убедившись, что автор этого хочет.
- Ссылки на код в доках — от корня репы, имена символов.
