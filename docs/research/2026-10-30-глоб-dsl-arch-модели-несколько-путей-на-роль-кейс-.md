# Разведка: глоб-DSL arch-модели — несколько путей на роль (кейс Java-бекендов)

> **Статус:** разведка · **Обновлено:** 2026-10-30
> **Суть:** роль arch-модели несёт ровно один глоб в `path` — на репе с Java-бекендами (ADR-015) из-за этого слои Clean невыразимы; обошлись грубыми ролями «одна на бекенд», потеряв охрану направления зависимостей. Просьба к тулзе: `path`-массив или брейс-расширение.
> **Связанное:** [ADR-014](../decisions/adr-014-arch-модель-devst-clean-на-бекендах-fsd-на-фронтах.md) · [ADR-015](../decisions/adr-015-java-бекенды-spring4-и-spring27.md) · [open-questions](../open-questions.md) · фича 16 (arch-модель)

> **Кому:** агент/автор devst. Отчёт самодостаточен — репа-потребитель не нужна, все факты внутри.

## 1. Контекст

- Инструмент: devst CLI, arch-модель (фича 16, ADR-030); проект polyglot-market (тир T2, стандарт v1.10, CLI v1.11).
- Модель: `docs/architecture/arch.model.json` — `schemaVersion: 1`, `defaultDeny: true`, роли с полем `path` (glob), матрица рёбер-разрешений.
- Триггер: сессия 12 (2026-10-30) — добавлены два Java-бекенда `backend/spring4` (Spring Boot 4.1.2) и `backend/spring27` (Boot 2.7.18), полный контракт, conformance 17/17 × 2.

## 2. Ограничение

Роль несёт **ровно один glob** в строковом поле `path`. Не поддерживаются:
- массив путей/глобов на роль;
- брейс-расширение `{a,b}` внутри глоба (уже числится в списке дыр: «глоб-DSL без `{a,b}` и без второго пути на роль»);
- любые другие способы объединить несколько мест в одну роль.

Роли с `slices: true` проблему не решают — это про слайсы FSD, не про объединение путей.

## 3. Реальный кейс (почему больно)

Слои Clean в существующих бекендах — **физические каталоги**, поэтому выразимы:

```json
"nest/domain":         { "path": "backend/nestjs/src/domain/**" },
"nest/presentation":   { "path": "backend/nestjs/src/presentation/**" }
```

В Java-бекендах (spring4/spring27, пакет `dev.polyglot.spring4|27`) код разложен по **фича-пакетам** (`auth`, `cart`, `orders`, `seller`, `staff`, `products`, `catalog`, `common`, `config`), а слои выражены **суффиксами классов**:

| Слой Clean | Файлы (разбросаны по всем фича-пакетам) |
|---|---|
| presentation | `**/*Controller.java`, `AuthFilter`, `RolesInterceptor`, `CurrentUserArgumentResolver`, `ApiExceptionHandler` |
| application | `**/*Service.java`, входные DTO |
| infrastructure | `**/*Repository.java`, `S3Storage`, `ImageThumbs`, `S3Props` |
| composition | `*Application.java`, `WebConfig` |

Желаемые роли `spring4/presentation|application|infrastructure` — это **множество глобов на роль**, одним `path` невыразимо.

**Обход (принят, верифицирован автором 2026-10-30: «Верифицирую — вноси»):**

```json
"spring4/backend":  { "path": "backend/spring4/src/**",  "why": "…одна роль, пока глоб-DSL не умеет несколько путей на роль" },
"spring27/backend": { "path": "backend/spring27/src/**", "why": "аналогично" },
// edges: у обоих [] — самодостаточны, кросс-импорты режет default-deny
```

**Цена обхода:** матрица не охраняет направление доменных зависимостей внутри Java-бекендов (`domain ← application ← presentation`), внутренние циклы слоёв не проверяются, arch map не рисует потоки слоёв — то есть arch-гарантии уровня nest/laravel для Java не действуют. `arch check` при этом зелёный: границ соблюдено, покрытие 38%→57% (362 файла вне ролей).

## 4. Просьба (семантика — на выбор реализации)

1. **Минимальная:** `path` принимает массив глобов:
   ```json
   "spring4/presentation": { "path": [
     "backend/spring4/src/**/*Controller.java",
     "backend/spring4/src/**/AuthFilter.java",
     "backend/spring4/src/**/RolesInterceptor.java" ], "why": "Clean: HTTP-слой" }
   ```
2. **Компактная:** брейс-расширение в глобе: `"backend/spring4/src/**/*{Controller,Filter,Interceptor,Advice}.java"` (закрывает заодно старую дыру `{a,b}`).
3. **Опционально:** суффикс-матчинг первоклассным полем роли (`"suffixes": ["Controller","Service","Repository"]`) — если массив глобов окажется дорог на больших репах.

Плюс желательно: `arch map`/`arch canon` показывают состав роли по каждому глобу (сколько файлов легло), чтобы грубые роли было видно сразу.

## 5. Приёмка (как поймём, что закрыто)

- Модель polyglot-market раскладывается до nest-подобных слоёв **без физической переложки кода** (4 роли на Java-бекенд, рёбра как у `nest/*`), `arch check` — 0 нарушений, направление зависимостей охраняется.
- Обратная совместимость: строковый `path` работает как раньше; старые модели не ломаются.
- `arch check` / `arch map` / `arch canon` / `blast` работают с массивом/брейсами без регрессий и таймаутов сверх обычных.
