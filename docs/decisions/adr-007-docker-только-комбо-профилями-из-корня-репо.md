# ADR-007: Docker только комбо-профилями из корня репо

> **Статус:** принято · **Дата:** 2026-10-19

**Суть:** Docker поднимает ровно «1 фронт + 1 бекенд + инфраструктура (Postgres, MinIO)». Режима «всё сразу» не существует. Все сборки — из корня репо; API-URL подставляется в runtime, не на этапе сборки.

**Отвергнуто:** `docker-compose up` всех 9+ сервисов — 4–6 ГБ RAM, рекрутер с ноутбуком не поднимет; `COPY` из-за пределов контекста — запрещено Docker'ом (баг исходного ТЗ); вшивание `VITE_API_URL` на build — пересборка ради смены адреса.

**Связанное:** [ADR-001](adr-001-postgresql-как-единственная-субд-во-всех-режимах.md) · [ADR-006](adr-006-один-активный-бекенд-одновременно.md) · features/05

## Контекст

Автор (в. 31): «давай чтобы у нас поднимался формат "1 фронт, 1 бек и всё что им нужно". "Все сразу" не поднимаем никогда». Дополнительно: в исходном ТЗ Dockerfile фронта делал `COPY ../../shared/...` — так нельзя, COPY видит только build-контекст.

## Опции

### A. Один compose со всеми сервисами и профилями

- Плюсы: декларативно, стандартный инструмент.
- Минусы: 14 комбинаций фронт × бек = раздутый файл,profiles-матрёшка.

### B. Генератор override-файла (`pnpm docker:up --front react --back nestjs`)

- Плюсы: одна базовая композиция (infra) + генерируемый override под пару; ровно 3–4 контейнера за раз; скрипт — сама витрина автоматизации.
- Минусы: свой код генерации YAML (~100 строк).

## Решение

**Вариант B.** `infra/docker-compose.infra.yml` (postgres, minio — общий) + `scripts/compose.js`, который рендерит `docker-compose.override.yml` для выбранной пары и зовёт `docker compose up`. Все `Dockerfile` строятся командой из корня: `docker build -f backend/nestjs/Dockerfile .` (контекст = корень).

Шаблоны Dockerfile — два вида:
- **SPA** (quasar, vue2, angular, react): multi-stage build → nginx + envsubst-шаблон `API_URL` в runtime.
- **SSR/нод** (nuxt, next, sveltekit, nestjs, laravel): node/php-процесс с `PORT`, `API_URL` через env.

Healthchecks у всех сервисов; миграции выполняет сервис бекенда на старте (или `docker:setup` из scripts).

## Обоснование

- Runtime-подстановка: один образ работает против любого бекенда без пересборки — это и есть правильный способ (решение автора в. 34: «делаем что правильнее»).
- Комбо-подъём совпадает с ментальной моделью репы «одна пара за раз» (ADR-006).

## Последствия

**Позитивные:** предсказуемое потребление RAM; образы кэшируются и переиспользуются между комбо.

**Негативные / риски:**
- `compose.js` — новый код (фича 05); шаблоны nginx надо тестировать (envsubst с дефолтом, если `API_URL` не задан).
