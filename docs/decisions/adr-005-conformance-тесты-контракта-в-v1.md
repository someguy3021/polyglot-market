# ADR-005: Conformance-тесты контракта в v1

> **Статус:** принято · **Дата:** 2026-10-19

**Суть:** единый набор HTTP-сценариев, который гоняется против любого бекенда и сверяет ответы со схемой OpenAPI (структура + форматы ошибок + пагинация). В составе v1, не «потом».

**Отвергнуто:** «conformance потом» — без него «2 бекенда = 1 API» остаётся заявлением, а не доказательством; Pact/Dredd — тяжеловесны и дряхлы для нашей задачи.

**Связанное:** [ADR-004](adr-004-openapi-3-0-3-и-генерация-sdk-typescript-axios.md) · [ADR-006](adr-006-один-активный-бекенд-одновременно.md) · features/01, 14

## Контекст

Главный экспонат репы — взаимозаменяемость бекендов. ИИ-скринер (приоритетный читатель, решение автора в. 1) и техлид должны видеть доказательство совместимости в виде исполняемого теста, а не абзаца в README.

## Опции

### A. Conformance «потом»

- Плюсы: быстрее первая работающая пара.
- Минусы: рассинхрон бекендов накопится до подключения тестов; главное обещание репы ничем не подкреплено.

### B. Свой раннер: fetch + JSON Schema валидация по OpenAPI (ajv)

- Плюсы: полный контроль сценариев (позитивные и негативные кейсы), минимум зависимостей, один код для обоих бекендов.
- Минусы: свой код надо поддерживать (но он небольшой).

### C. Dredd / Schemathesis

- Плюсы: готовые инструменты.
- Минусы: Dredd заброшен; Schemathesis — Python в тулчейне; оба плохо выражают семантику (формат ошибок, пагинация, идемпотентность).

## Решение

**Вариант B.** `packages/conformance/`: сценарии «запрос → ожидание по схеме» + семантические проверки. CI гоняет против Laravel и NestJS по очереди (см. ADR-006). Решение автора (в. 18): «да, сразу».

## Обоснование

- Conformance-раннер — это и тест, и витрина: рекрутер читает сценарии как спецификацию API.
- Негативные кейсы (битый JWT, чужой заказ, невалидное тело) — то, чего не даёт генераторный фаззинг.

## Последствия

**Позитивные:** доказуемая совместимость бекендов; сценарии переиспользуются E2E-слоем.

**Негативные / риски:**
- Раннер требует дисциплины: каждый новый эндпоинт = новые conformance-кейсы в том же PR (правило фиксируем в AGENTS.md, когда появится код).
