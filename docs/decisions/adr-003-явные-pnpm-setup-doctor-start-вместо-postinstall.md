# ADR-003: Явные pnpm setup / doctor / start вместо postinstall-магии

> **Статус:** принято · **Дата:** 2026-10-19

**Суть:** вся настройка — явные команды: `pnpm doctor` (проверка окружения) → `pnpm setup` (зависимости, .env, миграции, сиды) → `pnpm start` (панель). Никаких тяжёлых postinstall-хуков.

**Отвергнуто:** автонастройка в `postinstall` — падение `pnpm install` у рекрутера без PHP, конфликт с pnpm 10 (блокировка lifecycle-скриптов), непрозрачные отказы в CI.

**Связанное:** [ADR-002](adr-002-общие-sql-миграции-с-node-раннером.md) · features/05, 06

## Контекст

Исходное ТЗ вешало установку зависимостей, .env, миграции и генерацию клиентов на `postinstall`. Это роняет сам install на машинах без PHP/Java, ломает кэширование в CI и противоречит поведению pnpm 10 (сборочные скрипты зависимостей блокируются по умолчанию). Решение автора (вопрос 26): «лучше предсказуемость и надёжность».

## Опции

### A. postinstall-магия

- Плюсы: «wow, одна команда».
- Минусы: непредсказуемые отказы; install нельзя кэшировать отдельно от настройки.

### B. Явные команды

- Плюсы: каждый шаг виден, ошибка локализована, CI кэширует install отдельно от setup.
- Минусы: README на одну команду длиннее.

## Решение

**Вариант B.** Контракт команд:

| Команда | Что делает |
|---|---|
| `pnpm doctor` | проверяет окружение: Node, pnpm, Docker; PHP+Composer и Java — предупреждением (нужны не всем сценариям) |
| `pnpm setup` | install воркспейсов, composer install, .env из примеров, `db:migrate`, `db:seed` |
| `pnpm start` | панель управления (порт 5555) |
| `pnpm infra:up` / `infra:down` | PostgreSQL + MinIO |
| `pnpm db:migrate` / `db:seed` | схема и данные |
| `pnpm test:e2e` | E2E-матрица (фронт × бекенд) |

## Обоснование

- Отказ doctor'а с внятным сообщением («нет Docker — используй WSL2», см. ADR-009) в разы лучше падения install на 50-й секунде.
- README остаётся трёхшаговым: `pnpm doctor && pnpm setup && pnpm start`.

## Последствия

**Позитивные:** предсказуемость, кэшируемость, человекочитаемые ошибки.

**Негативные / риски:**
- Ленивый рекрутер может забыть `setup` → панель при старте проверяет флаг «setup выполнен» и показывает кнопку «Run setup» (фича 06).
