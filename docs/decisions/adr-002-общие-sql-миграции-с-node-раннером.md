# ADR-002: Общие SQL-миграции с Node-раннером

> **Статус:** принято · **Дата:** 2026-10-19

**Суть:** схема БД — общий набор `shared/db/migrations/*.sql`, который применяет Node-раннер (`pnpm db:migrate`). Оба ORM (Eloquent, TypeORM) только маппят готовую схему.

**Отвергнуто:** «миграции ведёт Laravel, NestJS отражает» — экстракт без PHP не может поднять БД; «свои миграции в каждом бекенде» — двойная поддержка, гарантированный рассинхрон.

**Связанное:** [ADR-001](adr-001-postgresql-как-единственная-субд-во-всех-режимах.md) · [ADR-003](adr-003-явные-pnpm-setup-doctor-start-вместо-postinstall.md) · features/02, 05

## Контекст

Экстракт «NestJS + фронт» обязан подниматься у рекрутера без установленного PHP (решение автора: «давай чтобы рекрутеру проще», вопрос 12). При этом схема одна на оба бекенда.

## Опции

### A. Миграции в Laravel

- Плюсы: идиоматично для Laravel-разработчика.
- Минусы: PHP обязателен везде; NestJS-экстракт мёртв без PHP.

### B. Свои миграции в каждом бекенде

- Плюсы: каждому бекенду родные инструменты.
- Минусы: две правды схемы; conformance-тесты будут ловить рассинхрон вечно.

### C. Общие SQL-миграции + Node-раннер

- Плюсы: PHP не нужен для схемы; одна правда; раннер — ~150 строк Node, тривиально тестируется.
- Минусы: artisan-миграции не используем (теряем Laravel-специфичный сахар); раннер надо написать.

## Решение

**Вариант C.** `shared/db/migrations/NNN_*.sql` (up-файлы; down не ведём — пересоздание из нуля дешевле поддержки даунов), таблица-журнал `schema_migrations` с чексуммами. Сиды — `shared/db/seeds/`, применяются `pnpm db:seed`.

## Обоснование

- Требование «рекрутеру проще» сильнее идиоматичности Laravel.
- TypeORM `synchronize: true` запрещён: схема меняется только миграциями (гонки и потеря данных при синке — известная проблема).

## Последствия

**Позитивные:**
- Любой экстракт поднимает БД одним Node-раннером.
- Схема диффается и ревьюится как SQL, независимо от ORM.

**Негативные / риски:**
- Laravel без artisan-миграций выглядит непривычно — компенсируем пояснением в `backend/laravel/README` со ссылкой на этот ADR.
- Раннер — новый код, который надо написать и покрыть тестами (фича 05).
