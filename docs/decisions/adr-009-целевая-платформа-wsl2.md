# ADR-009: Целевая платформа WSL2

> **Статус:** принято · **Дата:** 2026-10-19

**Суть:** репа целится в Linux-подобные среды: Linux, macOS, Windows через WSL2. Windows-native (спавн `.cmd`, дисковые пути `C:\`, `php artisan serve` вне WSL) не поддерживается и явно документирован.

**Отвергнуто:** кросс-платформенность Windows-native — двойная поддержка путей/процессов в менеджере и скриптах ради меньшинства аудитории.

**Связанное:** [ADR-001](adr-001-postgresql-как-единственная-субд-во-всех-режимах.md) · [ADR-003](adr-003-явные-pnpm-setup-doctor-start-вместо-postinstall.md) · features/05, 06

## Контекст

Автор работает в WSL (в. 27: «у меня WSL сейчас! Так что все именно под него»). Аудитория рекрутеров — преимущественно *nix; Windows-разработчики привычны к WSL2.

## Опции

### A. Кроссплатформенность вплоть до Windows-native

- Плюсы: «работает везде».
- Минусы: менеджер процессов (spawn, сигналы, пути), шелл-скрипты и Docker-пути ×2 сложность; тестировать не на чем.

### B. POSIX-мир + WSL2 для Windows

- Плюсы: один набор скриптов; CI (ubuntu) = целевой среде 1:1; WSL2 сегодня стандарт де-факто.
- Минусы: нужна явная надпись в README и проверка в `pnpm doctor`.

## Решение

**Вариант B.** Скрипты — Node (кроссплатформенный сам по себе) + POSIX-шелл; менеджер процессов использует POSIX-сигналы. `pnpm doctor` при запуске на Windows-native печатает: «используйте WSL2» и выходит. В README — таблица поддерживаемых сред (Linux, macOS, WSL2).

## Обоснование

- CI на ubuntu становится эталонной средой: «зелёный CI = заведётся у рекрутера».
- Экономия всей двойной работы с процессами и путями.

## Последствия

**Позитивные:** один тулчейн; CI-паритет с локальной средой.

**Негативные / риски:**
- Windows-рекрутер без WSL2 отсеивается — принимаем осознанно, README кричит об этом первой строкой раздела «Требования».

**Дополнение (2026-10-19, сессия 02):** WSL-VM гаснет при отсутствии процессов — вместе с ней умирают
контейнеры и проброс портов. `pnpm infra:up` держит VM живой отвязанным (setsid) sleep-процессом.
Соседние docker-проекты в том же WSL могут занимать хостовые порты (например 8000) — менеджер процессов
обязан уметь автоподбор свободного порта (фича 06).
