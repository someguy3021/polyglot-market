# ADR-001: PostgreSQL как единственная СУБД во всех режимах

> **Статус:** принято · **Дата:** 2026-10-19

**Суть:** один диалект БД на все режимы: Postgres в контейнере и нативно, и в Docker-комбо. SQLite не используется нигде.

**Отвергнуто:** два режима с разными СУБД (SQLite нативно / Postgres в Docker) — 4 комбинации «диалект × ORM», рассинхрон схемы, двойная проверка миграций.

**Связанное:** [ADR-002](adr-002-общие-sql-миграции-с-node-раннером.md) · [ADR-009](adr-009-целевая-платформа-wsl2.md) · features/05

## Контекст

Исходное ТЗ допускало SQLite нативно и PostgreSQL в Docker. Схема общая для двух ORM (Eloquent, TypeORM) — так получаем 4 места, где типы и поведение могут разъехаться. Плюс SQLite плохо держит параллельную запись и обесценивает сиды/миграции (их пришлось бы проверять на двух диалектах).

## Опции

### A. SQLite везде

- Плюсы: ноль внешних зависимостей в нативном режиме.
- Минусы: параллельная запись, volume-гимнастика в Docker, прод-непохожесть, различия ORM-типов остаются.

### B. PostgreSQL везде

- Плюсы: один диалект; jsonb, ограничения, честные типы; прод-подобная среда; миграции и сиды пишутся один раз.
- Минусы: Docker обязателен даже для «нативного» режима.

### C. Два режима с разными СУБД (исходное ТЗ)

- Минусы: максимальная площадь рассинхрона при минимальной демонстрационной ценности.

## Решение

**Вариант B.** «Нативный режим» означает: процессы приложений (бекенды, фронты, панель) живут вне Docker, но инфраструктура (PostgreSQL, MinIO) всегда поднимается контейнерами (`pnpm infra:up`).

## Обоснование

- Решение автора (2026-10-19, ответ на вопрос 11): «давай а» — вариант «PostgreSQL везде, нативный режим через docker compose up postgres».
- Репа демонстрирует компетенцию: показывать одинаковый код на двух диалектах — анти-демо.

## Последствия

**Позитивные:**
- Схема, миграции, сиды — один диалект, один набор проверок.
- jsonb, CHECK-констрейнты, транзакционная DDL доступны обоим бекендам.

**Негативные / риски:**
- Docker обязателен везде; целевая платформа — WSL2/Linux/macOS (см. ADR-009), Windows-native не поддерживается.
- Слоган «0 Docker» из старого ТЗ снят: теперь «приложения без контейнеров, инфраструктура в контейнерах».
