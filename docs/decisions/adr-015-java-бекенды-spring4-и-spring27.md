# ADR-015: Java-бекенды spring4 и spring27

> **Статус:** принято · **Дата:** 2026-10-30

**Суть:** витрина получает ещё два бекенда — `spring4` (Spring Boot 4.x, современный профиль) и `spring27` (Spring Boot 2.7.18, легаси-профиль). Все четыре бекенда (Laravel, NestJS, spring4, spring27) — взаимозаменяемые реализации одного контракта; инвариант ADR-006 «активен максимум один» не меняется.

**Отвергнуто:** Kotlin-бекенд (тот же Spring Boot на другом языке — добавляется позже дёшево, если автору нужно); JPA/Hibernate-маппинг схемы (PG-enums и numeric(10,2) через ORM добавляют настройки без пользы — схема уже зафиксирована общими миграциями, ADR-002); springdoc/Swagger UI сейчас (у NestJS/Laravel `/api/docs` не реализован — паритет).

**Связанное:** [ADR-002](adr-002-общие-sql-миграции-с-node-раннером.md) · [ADR-005](adr-005-conformance-тесты-контракта-в-v1.md) · [ADR-006](adr-006-один-активный-бекенд-одновременно.md) · [ADR-009](adr-009-целевая-платформа-wsl2.md) · [ADR-014](adr-014-arch-модель-devst-clean-на-бекендах-fsd-на-фронтах.md) · features/19, 20

## Контекст

- Автор решил (2026-10-30): «берём сразу ОБЕ — java-spring-4 и java-spring-2.7, 2 бекенда у нас будут» — расширение витрины с 2 до 4 бекендов: «самый свежий стек» и «самое популярное легаси» Java-мира.
- Репа декларировала «везде TypeScript на Node-стороне» — Java-бекенды сознательно нарушают принцип как отдельные экспонаты; принцип остаётся для обвязки (скрипты, панель, фронты).
- Java на машине: OpenJDK 21.0.10 (Microsoft), Maven отсутствовал (поставлен в `D:/AI_Cwork/tools/apache-maven-3.9.12`, вне репы).
- Порты: laravel 8010, nestjs 3000 заняты по факту; свободные 8020/8030 в репе и системе не заняты.

## Опции

### A. Два Spring-бекенда (взят)

- Плюсы: закрывает обе крайности вакансий — актуальный стек (Boot 4, Java 21+, виртуальные потоки) и легаси-энтерпрайз (Boot 2.7, Java 8-синтаксис, javax.*); одна кодовая база контракта на двух поколениях платформы — наглядная витрина.
- Минусы: два новых стека в обвязке (панель, e2e-матрица, doctor); легаси-профиль ограничивает выбор библиотек.

### B. Только spring4

- Плюсы: дешевле.
- Минусы: не закрывает половину Java-вакансий (легаси), автор сказал «обе».

### C. Kotlin-бекенд вместо одного из

- Плюсы: ещё одна модная строка в витрине.
- Минусы: Kotlin — тот же Spring Boot; добавляет шаг трансляции и не даёт легаси-профиля. Возможно позже отдельным ADR.

## Решение

**Вариант A.**

- **spring4** (`backend/spring4`): Spring Boot 4.1.x, Java 21 (baseline Boot 4 — 17; JDK 25 LTS — целевая рекомендация при обновлении тулчейна), виртуальные потоки включены (`spring.threads.virtual.enabled`), Spring MVC, Spring JDBC (`JdbcTemplate`), jakarta.*, Maven + wrapper, порты 8020.
- **spring27** (`backend/spring27`): Spring Boot 2.7.18 (последний 2.7), исходники на Java 8 (без var/records/switch-expressions), javax.*, Maven + wrapper, порт 8030; runtime — JDK 21 машины (код и зависимости уровня Java 8; прод того поколения — 8/11).
- Оба: чистая архитектура по ADR-014 (controller → service → repository, JDBC-репозитории в infrastructure), JWT HS256 с общим `JWT_SECRET` (claim `sub`, 24ч — взаимозаменяемо с Laravel/NestJS), общая PostgreSQL и MinIO, доступ только чтением/записью данных — схема меняется только общими SQL-миграциями (ADR-002), никаких собственных миграций.
- Обвязка: скрипты/панель/e2e-матрица (`--back=spring4|spring27`), doctor проверяет `java` (и подсказывает Maven/wrapper).

## Обоснование

- Виртуальные потоки (Loom) в spring4 — актуальный мейнстрим 2026: блокирующий код без реактивщины; на Boot 4 включается одним свойством.
- Boot 2.7.18 — последнее поколение javax-энтерпрайза (OSS-поддержка кончилась 2023-11, но в энтерпрайзе массово живёт) — ровно то «популярное легаси», что спрашивают в вакансиях.
- JdbcTemplate вместо JPA: PG-enums (user_role, product_status, order_status, promo_type) и numeric(10,2) маппятся нативно, `SELECT … FOR UPDATE` для чекаута пишется явно; ORM дал бы конфликт маппинга enum-типов на двух поколениях Hibernate.
- Паритет поведения обеспечивает conformance (ADR-005): тот же набор сценариев против обоих новых бекендов.

## Последствия

**Позитивные:**
- Витрина закрывает 4 стека бекендов; e2e-матрица расширяется флагом `--back=`, полная 4×7 — по требованию.
- Токены и данные полностью взаимозаменяемы со всеми бекендами (общие JWT/БД/S3).

**Негативные / риски:**
- Maven-зависимости тянутся из Central при первой сборке (в CI/докере — кэш); wrapper скачивает Maven сам.
- spring27 не имеет OSS-поддержки — только витринный экспонат.
- Docker-образы, экстракты фабрики (7×4), k8s-стенд и панель для Java-бекендов — следующие ходы (см. roadmap), в этом ADR не заявлены.
- JDK 25 на машине нет: spring4 собран на 21 (baseline 17); при обновлении тулчейна ничего в коде менять не требуется.
