# Roadmap — Фаза 3: второй бекенд

> **Статус:** В РАБОТЕ (3.1–3.2 готовы, 3.3 не начата) · **Обновлено:** 2026-10-20

**Суть:** NestJS добирается до байт-в-байт паритета с Laravel против того же контракта и той же БД.

**Цель:** conformance зелёный против обоих бекендов; заказ, созданный на Laravel, виден через NestJS; docker-комбо «1 фронт + 1 бек» поднимается скриптом.

Границы фазы:
- Никаких новых фронтов; панель — без изменений.

## Этапы

### 3.1 — NestJS (фича 04)

- [ ] Сущности поверх общей схемы, auth + роли
- [ ] Каталог/корзина/заказы/идемпотентность/промокоды/доставка
- [ ] Медиа (sharp + S3)
- [ ] Кабинеты ролей
- [ ] Юнит-тесты сервисов

### 3.2 — Паритет

- [x] Conformance против NestJS — 17/17 (весь набор, тот же что против Laravel)
- [ ] Сквозной E2E «Laravel заказ → NestJS видит» (фича 14)

### 3.3 — Docker-комбо (ADR-007)

- [ ] Шаблоны Dockerfile (SPA/SSR/Laravel/Nest) с runtime API_URL
- [ ] `scripts/compose.js`: подъём пары + infra, healthchecks
- [ ] Проверка двух комбо вручную (SPA-фронт и SSR-фронт)

## Критерии готовности

1. [x] Один и тот же conformance-набор зелёный против обоих бекендов без правок сценариев (17/17 Laravel :8010 и NestJS :3000).
2. [ ] Смена бекенда под живым фронт не меняет поведение (сценарий видео №4) — частично: API-сторона доказана conformance, UI-переключение — после 3.3.
3. [ ] `pnpm docker:up --front=quasar --back=nestjs` поднимает рабочую пару на чистой машине.

## Осознанные НЕ-цели фазы

- Параллельный запуск двух бекендов (ADR-006 запрещает).
