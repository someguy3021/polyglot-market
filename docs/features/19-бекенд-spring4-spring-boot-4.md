## 2. Сценарии

1. Рекрутер в панели: старт spring4 вместо NestJS → фронт продолжает работать (общая БД/токены).
2. CI: conformance 17/17 против spring4 — четвёртая реализация одного контракта.
3. Токен, выпущенный NestJS/Laravel, читается spring4 (общий `JWT_SECRET`, HS256, claim `sub`).

Детали реализации (`backend/spring4`, пакет `dev.polyglot.spring4`):
- Spring Boot 4.1.2, Java 21 на этой машине (baseline Boot 4 — 17; JDK 25 LTS — целевая рекомендация), `spring.threads.virtual.enabled=true`.
- Слои Clean (ADR-014): `presentation` (контроллеры) → `application`-сервисы → `products/cart/orders/auth`-репозитории на `JdbcClient` — ORM сознательно нет (PG-enums и numeric без боли, `SELECT … FOR UPDATE` явно, ADR-015).
- Jackson 3 (`tools.jackson`) — дефолт Boot 4; в `OrdersService` — сериализация `shipping_address` jsonb.
- jjwt 0.13; bcrypt-хеши пишутся с `$2y$`-префиксом — паритет с Laravel в общей таблице users.
- pgjdbc `stringtype=unspecified` — JDBC-строки приводятся PG к uuid/enum по колонке.
- Картинки: AWS SDK v2 (path-style на MinIO/s3rver) + ImageIO + TwelveMonkeys webp-ридер, превью 320×240 PNG (паритет sharp).
- Сборка: Maven + wrapper (`mvnw`), артефакт `target/spring4-1.0.0.jar`; конфиг — корневой `.env` (DB_*, S3_*, JWT_SECRET, PORT).
