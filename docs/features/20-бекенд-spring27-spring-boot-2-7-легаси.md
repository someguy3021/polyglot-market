# Фича: Бекенд spring27 (Spring Boot 2.7, легаси)

> **Статус:** АКТУАЛЬНО · **Обновлено:** 2026-10-30

**Суть:** четвёртая реализация контракта на «популярном легаси» Java-энтерпрайза: Spring Boot 2.7.18 (последний javax-поколения), исходники на Java 8. Ровно тот стек, что массово живёт в банках/энтерпрайзе и стоит в вакансиях (ADR-015).

**Ключевое:** решений в протоколе: 0 (решения — в ADR-015) · этапов: 1 из 3

## 1. Суть и потребители

| Потребитель | Как пользуется |
|---|---|
| 7 фронтов | тот же REST API (порт 8030), без единой правки фронта |

| Скринер | доказательство чтения/поддержки легаси-Java (javax, JdbcTemplate, SDK v1) |

## 2. Сценарии

1. Рекрутер: переключение фронтов на легаси-бекенд без правок — тот же контракт.
2. CI: conformance 17/17 против spring27 — один контракт на четырёх поколениях стеков.
3. Витрина «diff-стилей»: рядом с spring4 видно, что изменилось в Java за 8 лет (records→POJO, jakarta→javax, JdbcClient→JdbcTemplate, Jackson 3→2, jjwt 0.13→0.11).

Детали реализации (`backend/spring27`, пакет `dev.polyglot.spring27`):
- Spring Boot 2.7.18, `maven.compiler.release=8` — компилятор гарантирует отсутствие API новее Java 8 (без records/var/switch-expressions/List.of); runtime — JDK 21 машины.
- javax.* неймспейс (servlet, validation), Jackson 2 (`com.fasterxml`), jjwt 0.11 (`parserBuilder`), AWS SDK **v1** (`AmazonS3ClientBuilder`) — всё эпохосообразно.
- `JdbcTemplate` + `RowMapper` (POJO с публичными финальными полями вместо records — Jackson 2 сериализует public-поля из коробки; лямбды доступны и в Java 8, стиль типов — как до records).
- Слои те же, что в spring4 (ADR-014 Clean): контроллеры → сервисы → репозитории; ошибки — единый `@RestControllerAdvice` в формате контракта.
- pgjdbc `stringtype=unspecified` — как в spring4 (uuid/enum-колонки принимают JDBC-строки).
- bcrypt `$2y$`-префикс, общий `JWT_SECRET`, S3-превью 320×240 PNG — паритет с остальными тремя бекендами.

## 5. НЕ-цели

- Модернизация легаси (миграция на Boot 3) — экспонат и есть «как есть в энтерпрайзе».
- Lombok — не эпохосообразно для витрины и добавляет шаг компиляции; явные POJO.
