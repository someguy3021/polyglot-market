# Фича: Домен маркетплейса четыре роли

> **Статус:** В ПЛАНЕ · **Обновлено:** 2026-10-19

**Суть:** не магазин, а маркетплейс: продавцы выставляют товары, модератор пускает их в каталог, админ управляет всем, покупатель заказывает.

**Ключевое:** решений в протоколе: 6 · этапов: 6

**Связанное:** [ADR-002](../decisions/adr-002-общие-sql-миграции-с-node-раннером.md) · [ADR-008](../decisions/adr-008-медиа-minio-с-первого-дня.md) · [ADR-011](../decisions/adr-011-идемпотентность-заказов-через-idempotency-key.md) · features/01, 14

## 1. Суть и потребители

| Роль | Кабинет / действия |
|---|---|
| **Покупатель** (buyer) | каталог с фильтрами, карточка товара, корзина (гостевая + мердж), checkout (промокод, доставка), свои заказы, повторы |
| **Продавец** (seller) | CRUD своих товаров (черновик → на модерацию), картинки, вид своих заказов, выручка по своим товарам |
| **Модератор** (moderator) | очередь модерации товаров (approve/reject с причиной), повторная отправка на доработку |
| **Админ** (admin) | все товары/заказы/пользователи, смена ролей, статусы заказов, промокоды, способы доставки |

## 2. Сценарии

1. Покупатель без логина собирает корзину (`cart_token` в cookie), логинится — корзина мерджится с аккаунтной.
2. Продавец создаёт товар (черновик), грузит картинки в MinIO, отправляет на модерацию.
3. Модератор отклоняет товар с причиной → продавец видит причину, правит, отправляет снова.
4. Одобренный товар появляется в каталоге → покупатель заказывает с промокодом `WELCOME10` и доставкой «Курьер».
5. Повторный POST /orders с тем же `Idempotency-Key` возвращает исходный заказ (ADR-011).
6. Админ переводит заказ new → paid → shipped → done; покупатель видит статус.

Статусные машины:
- товар: `draft → pending_moderation → approved | rejected (→ pending_moderation)`
- заказ: `new → paid → shipped → done`, из `new|paid` — `cancelled`
- заказ пишется продавцу? Нет: заказ один, `order_items` ссылаются на товары разных продавцов; продавец видит свои строки.

## 3. Протокол решений

| № | Дата | Вопрос | Решение |
|---|---|---|---|
| 1 | 2026-10-19 | Ролевая модель | 4 роли: покупатель, продавец, админ, модератор (автор: «давай расширим и сильно… маркетплейс прямо») |
| 2 | 2026-10-19 | Гостевая корзина | делаем, с мерджем при логине (автор: «конечно делаем!») |
| 3 | 2026-10-19 | Checkout | промокоды и способы доставки — в v1 (автор: «давай… сделаем тоже») |
| 4 | 2026-10-19 | Картинки товаров | upload + MinIO + превью с первого дня (автор: «СРАЗУ… все серьезно») |
| 5 | 2026-10-19 | Идемпотентность заказа | Idempotency-Key обязателен (автор: «НУЖЕН») |
| 6 | 2026-10-19 | Отзывы/рейтинги, споры, выплаты продавцам | НЕ-цель v1 |

## 5. НЕ-цели

- Отзывы и рейтинги, споры/возвраты, выплаты продавцам, чат покупатель↔продавец — v2.
- Реальные платежи — только статусная модель `new → paid`.
