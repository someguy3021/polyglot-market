# Фича: Бекенд NestJS

> **Статус:** В ПЛАНЕ · **Обновлено:** 2026-10-19

**Суть:** вторая реализация полного контракта на актуальном NestJS: байт-в-байт совместимые ответы с Laravel против общего Postgres.

**Ключевое:** решений в протоколе: 3 · этапов: 7

**Связанное:** [ADR-001](../decisions/adr-001-postgresql-как-единственная-субд-во-всех-режимах.md) · [ADR-005](../decisions/adr-005-conformance-тесты-контракта-в-v1.md) · [ADR-006](../decisions/adr-006-один-активный-бекенд-одновременно.md) · features/01, 02, 03

## 1. Суть и потребители

| Потребитель | Как пользуется |
|---|---|
| 7 фронтов | тот же REST API (порт 3000), без единой правки фронта |
| conformance/e2e | цель №2 прогонов |
| Скринер | доказательство Node/TypeScript-компетенции |

## 2. Сценарии

1. Рекрутер в панели: стоп Laravel → старт NestJS → фронт продолжает работать (данные общие).
2. CI: conformance-раннер зелёный против обоих бекендов — доказательство «1 API, 2 реализации».
3. Загрузка картинки: multer-валидация → aws-sdk → sharp-превью — паритет с Laravel.

Детали реализации:
- Версии — актуальные stable на день старта кода (ориентир: Node 24 LTS, NestJS 11+); пины в `package.json`, `.nvmrc`.
- ORM: TypeORM, сущности маппят общую схему; `synchronize: false` — жёстко (ADR-002).
- Валидация DTO: class-validator; трансформация ответов в единый формат ошибок — глобальный exception filter.
- JWT: `@nestjs/jwt`; роли: guards (`RolesGuard`).
- Медиа: `@nestjs/platform-express` multer + `aws-sdk`/`@aws-sdk/client-s3` + `sharp`.
- Rate limit: `@nestjs/throttler`; CORS — whitelist origins.
- Юнит-тесты сервисов (Jest): корзина, заказ, промокоды.
